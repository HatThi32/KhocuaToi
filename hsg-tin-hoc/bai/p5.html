Vì sao cần đo độ phức tạp?

Hai chương trình đúng, một cái quá chậm

Cùng một bài, hai thuật toán đều đúng nhưng một cái chạy 1 giây, cái kia chạy cả giờ khi n lớn.

Đo bằng giây phụ thuộc máy; nên ta đếm số phép toán cơ bản theo cỡ dữ liệu n.

Độ phức tạp thời gian = cách số phép toán tăng khi n tăng.

def tong_cap(n):
    t = 0
    for i in range(1, n + 1):
        t += i
    return t

def tong_ct(n):
    return n * (n + 1) // 2

print(tong_cap(10**6), tong_ct(10**6))
Cùng kết quả
500000500000 500000500000
Cách 1: n phép cộng (O(n)). Cách 2: vài phép tính (O(1)). Với n = 10¹⁸, cách 1 không thể chạy xong.

Đếm số phép toán: vòng lặp đơn

Quy tắc

Vòng for i in range(n) chạy n lần; mỗi lần thực hiện số phép không đổi → tổng ≈ n.

Hai vòng lặp nối tiếp (không lồng): cộng số lần: n + n = 2n.

Hai vòng lồng nhau: nhân: n × n = n².

n = 1000
dem = 0
for i in range(n):
    dem += 1
for i in range(n):
    dem += 1
print(dem)
dem = 0
for i in range(n):
    for j in range(n):
        dem += 1
print(dem)
Nối tiếp: 2n; lồng nhau: n²

Kí hiệu O: bỏ hằng số và số hạng thấp

Quy tắc đơn giản hoá

Chỉ giữ số hạng lớn nhất khi n lớn và bỏ hệ số.

3n² + 5n + 20 → O(n²); 100n → O(n); n + log n → O(n); n log n + n² → O(n²).

O là cận trên: nói thuật toán “không chậm hơn cỡ” đó.

n log n + nO(n log n)

Vòng lặp lồng: n lần log n

n log n

Vòng ngoài n lần, vòng trong nhân đôi j: mỗi lượt log n → tổng O(n log n).

Đặc trưng của sắp xếp trộn, sắp xếp nhanh, heapsort.

n = 1024
ops = 0
for i in range(n):
    j = 1
    while j < n:
        ops += 1
        j *= 2
print(ops, n * 10)

Tổng điều hoà: n/1 + n/2 + … = n log n

Vòng lặp bước nhảy

for j in range(i, n+1, i) chạy n / i lần.

Tổng qua mọi i: n(1 + 1/2 + 1/3 + … + 1/n) ≈ n ln n → O(n log n).

Gặp ở sàng Eratosthenes.

n = 12
dem = 0
for i in range(1, n + 1):
    for j in range(i, n + 1, i):
        dem += 1
print(dem)
print(sum(n // i for i in range(1, n + 1)))

Lồng nhau mà vẫn O(n): kĩ thuật hai con trỏ

Đừng kết luận vội

Có vòng while trong vòng for nhưng biến j chỉ tăng, không quay lại: tổng số lần j tăng không quá n.

n = 1000

    while j < i:
        j += 1
        ops += 1
    ops += 1
print(ops)

Vòng lặp trong vòng lặp có điều kiện

Bài HSG: số lần phép d += 1

Vòng ngoài: i = n, n/2, n/4, … → log₂ n + 1 vòng. Mỗi vòng, vòng trong luôn chạy n lần.

Tổng ≈ n × (số lần chia đôi) → O(n log n).

def dem_phep(n):
    d = 0
    i = n
    while i > 0:
        j = 0
        while j < n:
            d += 1
            j += 1
        i //= 2
    return d
print(dem_phep(8), dem_phep(16), dem_phep(32))
Kết quả
32 80 192
n = 8: i = 8, 4, 2, 1 → 4 vòng × 8 = 32. n = 16: 5 × 16 = 80. n = 32: 6 × 32 = 192.

Ước lượng thời gian chạy từ giới hạn đề

Quy tắc kinh nghiệm

Python làm khoảng 10⁷ phép/giây (vòng lặp thuần), C++ khoảng 10⁸–10⁹. Đề HSG thường cho 1–2 giây.

Tính số phép = độ phức tạp(n): nếu vượt ~10⁷ với Python thì cần thuật toán tốt hơn.

Ví dụ n = 10⁵, O(n²) = 10¹⁰ → quá chậm; O(n log n) ≈ 1,7·10⁶ → được.

Giới hạn nThuật toán tối đa chấp nhận được
n ≤ 20O(2ⁿ) hoặc O(n!) nhỏ
n ≤ 1000O(n²)
n ≤ 10⁵O(n log n)
n ≤ 10⁶O(n)
n ≤ 10¹⁸O(log n) hoặc O(1)

Ví dụ: bài toán cặp tổng k

Ba cách giải một bài

Đếm cặp (i < j) có a[i] + a[j] = k.

Cách 1 hai vòng lồng: O(n²).

Cách 2 sắp xếp + hai con trỏ: O(n log n).

Cách 3 dùng dict đếm: O(n).

import time
def c1(a, k):
    return sum(1 for i in range(len(a)) for j in range(i+1, len(a)) if a[i]+a[j]==k)
def c3(a, k):
    d = {}; t = 0
    for x in a:
        t += d.get(k - x, 0)
        d[x] = d.get(x, 0) + 1
    return t
a = list(range(3000)) * 2
print(c1(a, 3000) == c3(a, 3000))
Hai cách cho cùng kết quả (n = 600)
597 597
Với n = 10⁵: cách 1 mất ≈ 10¹⁰ phép — không kịp; cách 3 chỉ ≈ 10⁵.

Vì sao “x in list” chậm, “x in set” nhanh?

Chi phí các thao tác

Thao táclistset / dict
x in …O(n)O(1) trung bình
thêm cuốiO(1)O(1)
a.pop(0)O(n)—

“Có phần tử trùng”: set cho O(n), list cho O(n²).

def trung(a, dung_set):
    seen = set() if dung_set else []
    for x in a:
        if x in seen:
            return True
        seen.add(x) if dung_set else seen.append(x)
    return False
print(trung([1, 2, 3, 1], True), trung([1, 2, 3], False))
Kết quả
True False
Dùng list: O(n²); dùng set: O(n).

Tốt nhất, trung bình, xấu nhất

Ba trường hợp

Tìm tuần tự x trong dãy n phần tử: tốt nhất 1 phép (x ở đầu); trung bình ≈ n/2; xấu nhất n (ở cuối hoặc không có).

Thường đánh giá theo trường hợp xấu nhất vì đó là cận trên đảm bảo.

n/2 và n cùng bậc O(n): không phải hai độ phức tạp khác nhau.

a = [7, 3, 9, 3, 5, 8]
def tim(a, k):
    dem = 0
    for i in range(len(a)):
        dem += 1
        if a[i] == k:
            return i, dem
    return -1, dem
print(tim(a, 7), tim(a, 3), tim(a, 8), tim(a, 4))
(vị trí, số lần so sánh)
(0, 1) (1, 2) (5, 6) (-1, 6)

Độ phức tạp bộ nhớ

Không gian phụ

Đo lượng bộ nhớ thêm ngoài dữ liệu vào, theo n.

O(1): chỉ vài biến (đảo danh sách bằng hai chỉ số đổi chỗ tại chỗ).

O(n): tạo danh sách mới cùng cỡ; đệ quy sâu n cũng tốn O(n) ngăn xếp.

Đổi thời gian lấy bộ nhớ hoặc ngược lại (ví dụ dùng set để nhanh hơn).

def dao_tai_cho(a):
    i, j = 0, len(a) - 1
    while i < j:
        a[i], a[j] = a[j], a[i]
        i += 1
        j -= 1
    return a
print(dao_tai_cho([1, 2, 3, 4, 5]))
b = [1, 2, 3][::-1]
print(b)
Kết quả
[5, 4, 3, 2, 1]
[3, 2, 1]
a[::-1] tạo bản sao nên tốn O(n) bộ nhớ; hai chỉ số chỉ O(1).

Tính dem (không chạy máy) rồi kiểm tra.

TRỌNG TÂM

Những điều phải nhớ

Ghi nhớ

  • Độ phức tạp là cách số phép toán tăng theo n; kí hiệu O giữ số hạng lớn nhất, bỏ hệ số.
  • Nối tiếp thì cộng, lồng nhau thì nhân; vòng nhân đôi cho log n.
  • Vòng lồng phụ thuộc: tổng n(n+1)/2 (O(n²)); bước nhảy i cho n log n.
  • Hai con trỏ có thể O(n) dù lồng nhau.
  • Đánh giá theo trường hợp xấu nhất; n/2 và n cùng bậc.
  • Ước lượng thời gian: Python ≈ 10⁷ phép/giây → chọn thuật toán theo giới hạn n.

NÂNG CAO

Điều dễ nhầm và mở rộng

Bẫy thường gặp

  • a.pop(0), a.insert(0, x) là O(n).
  • x in list là O(n), x in set là O(1).
  • sorted là O(n log n).
  • Nên giữ bộ nhớ trong giới hạn đề (thường 256 MB).

Mở rộng

  • Độ phức tạp khấu hao (amortized) của append.
  • Định lí thợ (Master theorem) cho đệ quy.
  • NP-đầy đủ và lớp bài khó.
